# EPPlus corresponding source and replacement

Binary packages ship the original EPPlus 4.5.3.3 DLL as a separate replaceable assembly, together with the package's LGPL text, GPL v3 text and the upstream corresponding source archive. No EPPlus 5+ code or commercial EPPlus licence is used. `tools/epplus-source.json` pins the upstream Version 4.5.3.3 commit and source-archive SHA-256. The original `EPPlus/EPPlus.MultiTarget.csproj` declares AssemblyVersion/FileVersion/Version 4.5.3.3 and netstandard2.1/netstandard2.0/net35/net40 targets. Package generation verifies those declarations before including the archive.

The application is dynamically linked; it is not trimmed, AOT-compiled or bundled into a single file. The application source and build recipes remain available under MIT. You may modify the LGPL library and reverse-engineer the combined application for debugging those modifications as permitted by the applicable LGPL; this project imposes no additional restriction on that use.

To rebuild the library, extract the bundled source archive and follow its original build/project instructions. For the .NET target consumed by this application, use the original multi-target project and a compatible .NET SDK/toolchain, for example `dotnet build EPPlus/EPPlus.MultiTarget.csproj -c Release -f netstandard2.1`. Older .NET Framework targets may require their reference assemblies/toolchains. Preserve the upstream assembly identity and public API expected by this application, then replace `EPPlus.dll` beside `ShopifyAdministration.Desktop.dll` in a copy of the unpacked portable installation. Keep the original DLL as a backup. Run the application's offline export regression/smoke checks against the modified library before use.

For a macOS bundle, the assemblies are in `Shopify Administration.app/Contents/MacOS`; modifications invalidate a distribution signature and a locally modified bundle may require your own local signing. For integrity-protected ClickOnce installations, use the portable distribution or rebuild/re-sign/re-publish your own deployment from the available source rather than overwriting a hash-protected installed file. Release packages must provide the portable/rebuildable alternative alongside such deployment modes. Updating a package may replace local library modifications; keep your source/build separately.

The unmodified source archive, notices and replacement instructions must remain available alongside distributed binaries; a moving upstream branch or an EPPlus 5+ source tree is not a substitute.
